為什麼需要這頁：Raspberry Pi 5 跑 Raspberry Pi OS（Linux）。你的開發機是 Windows 或 macOS，但板子跑 Linux——連線、燒錄、傳檔、文字編碼的做法在兩種系統差異很大。

1. Windows 開發者：怎麼做

1.1 SSH 連線（三種方式）

方式 A：Windows 10/11 內建 OpenSSH（PowerShell）
ssh ubuntu@
方式 B：WSL2（推薦，最接近 Linux 開發環境）
# 在 WSL2 終端內，與 Linux 行為一致
ssh ubuntu@
scp 檔名 ubuntu@:/home/...

方式 C（舊習慣）：PuTTY——Host 填 IP、Port 22、連線類型 SSH。

Windows 注意：① 若 ssh 無法辨識，安裝「OpenSSH 用戶端」（設定→選用功能）② 連不上先 ping 確認同網段、關閉對 ssh 的防火牆干擾。

1.2 映像燒錄（SD 卡 / eMMC）

Raspberry Pi Imager（Win）
1. 下載安裝 Raspberry Pi Imager
2. 選裝置 → 選映像（可先設定 ssh/wifi/帳號）
3. 選 SD 卡 → 寫入
Windows 陷阱：Windows 常把 SD 卡視為「可移動磁碟」，寫入前會跳出權限確認——不要誤選硬碟。燒完 Windows 可能顯示「要格式化」——忽略，那是 Linux 分割。

1.3 檔案傳輸

WinSCP（GUI）
主機:   使用者: ubuntu  密碼/金鑰
拖曳即可上傳/下載；可保留或轉換換行符（LF/CRLF）
PowerShell scp
scp .\tuning.json ubuntu@:/home/ubuntu/

1.4 序列埠（Console）

PuTTY 序列
連線類型: Serial
Serial line: COM3（裝置管理員確認）
Speed: 115200

1.5 Windows 必踩雷清單

  • CRLF vs LF：Windows 編輯器存的檔案含 \r\n，丟上 Linux 後 bash/python 常報錯。VS Code 右下角切「LF」，或上板後 dos2unix 檔名。
  • UTF-8 / BOM：中文註解與設定檔用 UTF-8（無 BOM）。記事本另存會加 BOM → 用 VS Code / Notepad++。
  • 路徑分隔：Windows 用 \、Linux 用 /。scp/ssh 內一律 /。
  • 別用記事本改重要設定：可能改壞編碼與換行。
  • PowerShell 引號：參數含特殊字元要正確跳脫，習慣用單引號。

2. macOS 開發者：怎麼做

2.1 SSH 連線（內建）

Terminal
ssh ubuntu@
# 可用 Bonjour 主機名：raspberrypi.local
序列埠 console
ls /dev/cu.usbserial-*        # 找 USB 轉序列裝置
screen /dev/cu.usbserial-XXXX 115200
# 離開：Ctrl-A 然後 K（再 Y）

2.2 映像燒錄

Raspberry Pi Imager / balenaEtcher（推薦）
下載映像 → 選磁碟 → 寫入
或 dd（進階）
diskutil list                          # 找 SD 卡磁碟識別碼
diskutil unmountDisk /dev/diskN
sudo dd if=映像.img of=/dev/rdiskN bs=4m status=progress
diskutil eject /dev/diskN
macOS 陷阱（最重要）：dd 用 /dev/rdiskN（raw），比 disk 快很多；但選錯磁碟 = 資料全毀。務必先 diskutil list 再三確認。

2.3 檔案傳輸

scp / rsync
scp tuning.json ubuntu@:/home/ubuntu/
rsync -avz ./資料夾/ ubuntu@:/home/ubuntu/資料夾/

2.4 macOS 必踩雷清單

  • 隱藏檔：.nojekyll、.git 以點開頭，Finder 看不到 → 用 ls -la。
  • 金鑰權限：SSH 私鑰要 chmod 600、~/.ssh 要 700，否則 ssh 拒絕。
  • 換行：mac 也是 LF，較少問題；從 Windows 拷過來的檔要 dos2unix。
  • 終端編碼：Terminal 用 UTF-8，避免中文亂碼。
  • 從 Windows 轉來的同事檔案：常帶 CRLF 與 BOM——接手先檢查。

3. Windows vs macOS 差異一覽（重點）

面向WindowsmacOS誰更省事
SSH 內建Win10+ 內建（要開選用功能）原生內建macOS
最接近 Linux 的環境WSL2（需安裝）Terminal 即類 UnixmacOS 開箱即用；WSL2 後 Windows 也行
序列埠需 PuTTY/Tera Term + 驅動內建 screen，需 USB 驅動差不多
燒錄風險誤選磁碟機dd 誤選磁碟 = 資料全毀都用 Imager 最安全
換行陷阱高（CRLF 常踩）低（LF）macOS
中文編碼易遇 ANSI/Big5預設 UTF-8macOS
給 Windows 開發者的最省心路徑：裝 WSL2 + VS Code（Remote-SSH）——之後所有指令都跟 macOS/Linux 一致，繞開 CRLF 與路徑問題。給 macOS 開發者：直接 Terminal + scp/rsync + VS Code Remote-SSH 即可。

4. 與本課操作流程的銜接

建立好連線與傳檔後，後續課程的每個單元都能照做：

  • 單元 3/6：在板上的 terminal 執行 i2cdetect、i2ctransfer（Windows 用 WSL/PuTTY；macOS 用內建 ssh）。
  • 單元 5：rpicam-* 指令與 RAW/DNG 下載回主機分析。
  • 單元 14：tuning 檔用 VS Code 在本機編輯（UTF-8 + LF）→ scp 上板 → 重啟測試。
