6.1 上電時序（OV5647）

步域電壓時序
1AVDD2.8 V先穩定
2DOVDD1.8 V相依
3DVDD1.5 V再穩定
4XCLK24 MHz電源後
5RESET—XCLK 後 ≥ 若干 ms
6I2C—RESET 後才可通
最常見錯誤：RESET 未釋放就下 I2C → register「看似能寫但沒生效」。官方模組 overlay 管理；客製板自製時序。

6.2 PLL：從 XCLK 到位元流（位元級）

Register欄位典型意義
0x3034pre-div0x18輸入分頻
0x3035div0x31VCO 分頻
0x3036multiplier0x69VCO 倍頻
0x3037ctrl/lock0x11可查 lock bit
工程檢查：改 PLL 前記錄 0x3037，改後回讀。PLL 錯 → fps 異常或全黑。以 ov5647.c ov5647_2lane_480Mbps 表為準。

6.3 MIPI 介面 register

Register功能典型
0x4740MIPI 控制0x22
0x4741lane 數0x00（2-lane）
0x4742clock/data0x0b

6.5 完整決策樹

「相機沒畫面」
1. list-cameras
   ├─ 空 ─→ 排線? dmesg error?
   │        "ov5647 probe failure" → 電源/clock/位址
   └─ 有 ─┐
2. i2cdetect 看到 0x36?
   ├─ 無 ─→ 上電/reset/位址
   └─ 有 ─┐
3. 讀 0x300A/B = 0x56/0x47?
   ├─ 錯 ─→ 別顆感測器? 位址錯?
   └─ 對 ─┐
4. 預覽
   ├─ 黑 ─→ 曝光 0? AE? 鏡頭蓋? banding?
   └─ 有 ── bring-up ✅

6.6 Register dump 完整範例

dump 曝光與 PLL
for r in 0x300a 0x300b 0x3034 0x3035 0x3036 0x3037          0x3500 0x3501 0x3502 0x3503 0x350a 0x350b; do
  h=${r:2:2}; l=${r:4:2}
  printf "%s: " "$r"; sudo i2ctransfer -y 22 w2@0x36 0x$h 0x$l r1
done
看完這單元你應該能說出：
  • 上電時序六步。
  • PLL register 位元級。
  • MIPI register。
  • media 管線走查。
  • 完整決策樹與 dump。
