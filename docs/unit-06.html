Bring-up 四件事

檢查項驗證工具
電源AVDD/DOVDD/DVDD 到位、時序示波器 / 電表
ClockXCLK 有輸出、PLL 鎖定示波器 / register

MIPImedia graph、dmesg 無錯media-ctl / dmesg

上電時序（重要）

電源穩定→XCLK→RESET 釋放（t≥若干 ms）→I2C 可通→MIPI 輸出
最常見錯誤：RESET 未釋放就下 I2C——register「看似能寫但沒生效」。OV5647 的 RESET 由 CAM_GPIO 控制，overlay 已處理；客製板要自己確保時序。

PLL / Clock（OV5647）

XCLK 典型 24 MHz，感測器內 PLL 產生主時脈。PLL 錯 → 畫面異常 fps 或全黑。

Register功能常見值
0x3034MIPI 10-bit PLL pre-div0x18
0x3035PLL divider0x31
0x3036PLL multiplier0x69
0x3037PLL control（含 lock bit）0x11

這些是驅動在 init 時寫入的公開範例值；以 ov5647.c 的 ov5647_2lane_480Mbps 表為準。

用 media-ctl 看整條管線

media graph
sudo media-ctl -p -d /dev/media0
# 預期看到：ov5647 → unicam（CSI-2）→ 各 stream 節點

Bring-up 決策樹

「相機沒畫面」決策樹
1. rpicam-hello --list-cameras 有相機？
   ├─ 沒有 → 檢查 overlay / dmesg / 排線
   └─ 有 ─┐
2. i2cdetect 看到 0x36？讀到 0x5647？
   ├─ 沒有 → 電源/reset/I2C 位址問題
   └─ 有 ─┐
3. rpicam-hello 預覽？
   ├─ 黑 → 曝光 0 / AE 未跑 / 鏡頭蓋
   └─ 有畫面 ─ 完成基本 bring-up ✅

Register dump 實作

dump 一組 register
# 讀曝光相關三 register
for r in 0x3500 0x3501 0x3502 0x3503; do
  echo -n "$r: "; sudo i2ctransfer -y 22 w2@0x36 ${r:2:2} ${r:4:2} r1
done
