4.2 資料流：Control → 驅動 → register → 統計

你設 ExposureTime=20000→libcamera 轉換→ov5647.c 寫 0x3500…→ISP 統計回饋→IPA 調整下一幀

你操作的是高階控制；libcamera 負責「控制 → register」轉換。理解這層，tuning 才看得懂。

4.3 unicam：CSI-2 接收器

  • unicam 收集 MIPI 資料流，對應 V4L2 media 節點。
  • 處理：lane 對齊、EAV/SAV 解碼、frame 同步。
確認 unicam 節點
ls /dev/video* /dev/media*
media-ctl -p -d /dev/media0 | head -30

4.4 DT overlay：感測器如何被發現（內容逐項）

ov5647 overlay 宣告（概念，欄位意義）
compatible = "ovti,ov5647";     # 匹配驅動
reg = <0x36>;                    # I2C 位址
clocks = <&cam0_clk>;              # XCLK 來源
reset-gpios = <...>;             # RESET 腳位（CAM_GPIO）
pwdn-gpios = <...>;              # PWDN（如有）
port { csi-lane = <2>; }          # MIPI 2-lane
欄位驅動用途
compatible與 of_device_id 匹配 → 載入 ov5647 驅動
regprobe 時 i2c_new_client_device 使用的位址
clocks供給 XCLK（pixel clock）
reset-gpios驅動 probe 時先 reset
確認 overlay 生效
sudo dtoverlay -a | grep ov56
dmesg | grep -i -E "ov5647|unicam"
