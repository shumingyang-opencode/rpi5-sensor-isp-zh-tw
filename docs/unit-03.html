OV5647 的 I2C 配置

項目值
7-bit 位址0x36
register 位址寬度16-bit（高 byte 在前）
RPi 匯流排i2c-22（Camera 0）/ i2c-10（Camera 1）
總線速度400 kHz（I2C 快速模式）

動手一：掃描匯流排找感測器

i2cdetect
sudo i2cdetect -y 22
# 預期輸出：在 0x36 出現 "36"（有裝置回應）
# 若空無一物 → 上電/reset/I2C 位址問題（見單元 6）

動手二：讀感測器 ID（bring-up 第一步）

讀 0x300A / 0x300B
sudo i2cget -y 22 0x36 0x300a
# 預期：0x56（OV5647 型號 byte）
sudo i2cget -y 22 0x36 0x300b
# 預期：0x47
# 完整：0x5647 → 確認是 OV5647
為什麼讀 ID：這是最快的「感測器是否活著」測試。讀得到 = 上電、reset、I2C 都對。

動手三：讀寫 register（含 page）

OV5647 有 bank（page）機制：部分 register 需先切換 0xFD/0xFE 或依 0x3008 的 bank bit 才能存取。

i2ctransfer 讀寫（16-bit 位址）
# 寫 register 0x3034 = 0x1E（PLL 設定範例）
sudo i2ctransfer -y 22 w3@0x36 0x30 0x34 0x1e
# 回讀驗證
sudo i2ctransfer -y 22 w2@0x36 0x30 0x34 r1
# 預期輸出：0x1e

i2cget 適合 8-bit 位址感測器；OV 用 16-bit 位址，習慣用 i2ctransfer。

關鍵 register 群（後續單元會用到）

Register功能用途
0x300A/0x300B感測器 ID驗證裝置
0x3034–0x3037PLL / clock單元 6
0x3500–0x3503曝光時間單元 10（AE）
0x350A–0x350B類比增益單元 10（AE）
0x4740–0x4742MIPI 介面單元 6
警告：正式流程請透過感測器驅動設定 register（libcamera 控制），手動 i2ctransfer 只適合除錯與理解。寫壞 register 可能讓感測器當機（重上電可回復）。
看完這單元你應該能說出：
  • OV5647 的 I2C 配置（位址/16-bit 位址/匯流排）。
  • 用 i2cdetect 掃描、用 i2ctransfer 讀寫。
  • 讀 0x300A/0x300B 驗證感測器身分。
  • OV page 機制與關鍵 register 群。
